2,800+ students recording their work

The finished file is the easiest part to fake.

Similarity checkers compare final submissions, and AI tools now produce final submissions on demand. What’s much harder to produce is the afternoon behind one: the false starts, the deleted lines, the test that finally passed at 11:40 p.m.

Every edit is a link.

The recorder runs inside the student’s editor. Each change, paste, save and shift of focus becomes an event, and each event is hashed together with the one before it. What you get is the work itself, in the order it happened, sealed into a chain.

  1. SHA-256, each event bound to the one before
  2. checkpoints signed as the student works
  3. handed in with the work

Change one link, and the chain says so.

Rewrite an event after the fact and its hash stops matching. Every event after it fails too, all the way to the end. Go ahead: pull a link out of the chain. Go ahead: tap a link to tamper with it. Go ahead: tamper with one event and watch the ledger.

    Evidence, not a guess.

    AI detectors read finished code and return a probability. The scores are unreliable, and no student can argue with one. Provenance doesn’t score code at all. It shows how the code came to exist: what was typed, what was pasted, and what changed while the editor wasn’t looking.

    A flag is a question, not a verdict. Every case goes to a person, with the whole session to replay.

    Two halves, one record.

    The recorder

    in the editor

    Runs in VS Code, JetBrains IDEs and Neovim. Works offline. Watches the assignment folder and nothing else.

    The bundle

    with the submission

    The signed log, handed in alongside the code.

    The analyzer

    in the browser

    Where course staff review. See a whole cohort at once, then replay any submission edit by edit. Every signal can be weighted or switched off by your staff, and cross-submission checks catch the same paste turning up in different students’ work.

    It works for you, too.

    If you did the work, the record is the best evidence you have that you did it. Here is exactly what it sees.

    Recorded

    • Edits and pastes in the assignment folder
    • Saves, opened files and editor focus
    • Commands run in the editor’s terminal
    • Which editor extensions are installed

    Never recorded

    • Anything outside the assignment folder
    • Your browser, screen, camera or other projects
    • Keystrokes at the system level
    • Your clipboard, unless you paste into the work

    No network requests while you work. The log stays on your computer until you hand it in, and it’s plain text you can read.

    What it can’t do.

    No log is impossible to forge. Someone with enough time and skill can fake one, and our own design documents say so. Provenance is built so the easy shortcuts leave marks, and the hard ones cost more effort than the assignment. The source is public, and the design assumes it.

    “We will know if you do something obvious, and we will know enough to ask questions if you do something subtle.”

    Provenance design document, section 6
